### 프롬프트 #26: 사업 모델 평가기

**프롬프트:**
```
다음 사업 아이디어를 구조화된 프레임워크로 평가해 주세요.

**사업 아이디어:** [2~3문장으로 설명]
**목표 시장:** [타겟 고객]
**수익 모델:** [수익 창출 방법]
**보유 자원:** [투입 가능한 시간, 자금, 역량, 팀 구성]

아래 기준 각각에 대해 1~10점으로 평가하고, 근거를 제시해 주세요:

1. **시장 규모** — 충분히 큰 시장인가?
2. **문제의 심각도** — 얼마나 절실한 문제인가? (비타민 vs 진통제)
3. **지불 의향** — 실제로 돈을 낼까? 근거는?
4. **경쟁 환경** — 기존 플레이어는? 차별화 포인트(해자)는?
5. **실행 난이도** — 구현/제공이 얼마나 어려운가?
6. **매출 발생 속도** — 첫 매출까지 걸리는 시간은?
7. **확장성** — 비용 비례 이상의 성장이 가능한가?
8. **경쟁 우위** — 남들이 갖지 못한 나만의 강점은?
9. **유닛 이코노믹스** — CAC, LTV, 마진이 맞는가?
10. **개인 적합도** — 내 역량과 관심사에 맞는가?

최종 결과:
- **종합 점수** (/100) + 등급: 🟢 실행 | 🟡 조건부 진행 | 🔴 재검토
- **Top 3 리스크**와 각각의 검증/완화 방법
- **최소 검증 실험** — 10만 원 이내, 1주 이내로 수요를 검증할 수 있는 방법
- **솔직한 한마디:** 1문단으로 객관적 평가
```

**사용 예시:**
- **사업 아이디어:** AI 기반 이력서 자동 작성 서비스 — 사용자의 경력 정보를 붙여넣으면 채용 공고에 맞춤화된 이력서를 AI가 생성. 건당 9,900원 또는 월 19,900원 무제한 플랜.
- **목표 시장:** 이직 준비 중인 3~7년 차 직장인
- **수익 모델:** 구독형 + 건별 과금 혼합
- **보유 자원:** 개발자 1명, 마케터 1명, 초기 자본 500만 원

**예상 결과:**
확증편향 없이 구조적으로 사업성을 진단한 평가표. 특히 '최소 검증 실험' 항목이 핵심 — 개발 전에 시장 반응을 확인할 수 있는 구체적 방법을 제시합니다.

### 프롬프트 #27: OKR 설계사

**프롬프트:**
```
[팀/회사/개인]의 OKR(목표 및 핵심 결과)을 작성해 주세요.

**맥락:**
- 적용 기간: [예: 2026년 1분기 / 상반기 / 연간]
- 회사(팀) 미션: [미션]
- 현재 가장 큰 과제: [과제 1], [과제 2]
- 지난 분기 성과 요약: [간단한 요약]
- 전략적 우선순위: [우선순위 1], [우선순위 2]

3~5개 Objective, 각각 3~4개 Key Result를 작성:

## Objective 1: [야심 차고, 정성적이며, 영감을 주는 목표]
| KR# | 핵심 결과 | 현재치 | 목표치 | 측정 방법 |
|-----|----------|--------|--------|----------|
| 1.1 | [구체적, 측정 가능, 기한 명시] | [기준값] | [목표값] | [측정 도구/방법] |
| 1.2 | | | | |
| 1.3 | | | | |

**실행 과제(Initiative):**
- [ ] 실행 과제 1
- [ ] 실행 과제 2

[각 Objective에 대해 반복]

## OKR 품질 점검:
- ✅ 각 Objective는 야심적이되 달성 가능 (60~70% 자신감)
- ✅ Key Result는 활동이 아닌 결과(outcome)인가
- ✅ Key Result에 수치가 포함되어 있는가
- ✅ Objective 5개 이하인가
- ✅ 상위 미션과 정렬되는가
- ✅ OKR 간 의존관계가 식별되었는가

## 트래킹 주기:
- 주간: [확인 항목]
- 월간: [리뷰 항목]
- 분기말: [점수 산정 방법]
```

**사용 예시:**
- **적용 대상:** 15인 B2B SaaS 스타트업, 2026년 1분기
- **미션:** 중소기업의 업무 자동화를 통해 생산성을 혁신한다
- **과제:** 이탈률 감소, 매출 성장
- **지난 분기:** MRR 3,000만 원, 이탈률 8%
- **우선순위:** 제품 안정성 강화, 엔터프라이즈 고객 확보

**예상 결과:**
측정 가능한 Key Result, 추적 방법, 품질 점검을 포함한 완성된 OKR 프레임워크. 보통 2~3회의 회의가 필요한 OKR 수립을 한 번에 정리합니다.

# 📋 부록

## 더 좋은 결과를 얻는 방법

### 1. 프롬프트를 체이닝하세요
한 번에 모든 것을 요구하지 마세요. 이 프롬프트들을 시작점으로 삼고, 후속 요청을 이어가세요:
- "톤을 좀 더 캐주얼하게 바꿔줘"
- "3번 포인트를 더 구체적으로 확장해줘"
- "B 옵션처럼 5개 더 만들어줘"
- "이걸 트위터 대신 링크드인 버전으로 바꿔줘"

### 2. 맥락을 풍부하게 제공하세요
맥락이 많을수록 결과가 좋아집니다:
- ❌ "AI에 대한 블로그 글 써줘"
- ✅ "AI에 회의적이지만 호기심은 있는 비전공자 소상공인을 위한 AI 생산성 도구 블로그 글 써줘. 톤: 친근한 전문가. 분량: 2,000자."

### 3. 역할 프롬프팅을 활용하세요
"당신은 [전문가 역할]입니다"로 시작하면 출력 품질이 일관되게 올라갑니다. 이 팩의 모든 프롬프트가 이 기법을 사용합니다.

### 4. 재생성보다 반복 수정하세요
결과가 70% 맞다면, 나머지 30%에 대해 구체적 피드백을 주세요:
- "구조는 좋은데, 예시를 SaaS에 더 맞게 바꿔줘"
- "1~3번은 훌륭해. 4번이 너무 일반적이야. 더 실행 가능한 걸로 교체해줘"

### 5. 최고의 결과물을 템플릿으로 저장하세요
완벽한 결과를 얻었다면 저장해두세요. 다음에 예시로 활용:
- "이 스타일로 써줘: [예시 붙여넣기]"
