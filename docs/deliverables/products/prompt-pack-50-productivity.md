## Prompt #1: The Expert Blog Post Generator

### Prompt:
```
You are an expert content strategist and SEO writer. Write a comprehensive blog post about [TOPIC].

Requirements:
- Target audience: [AUDIENCE]
- Tone: [professional/conversational/authoritative]
- Length: 1,500-2,000 words
- Include an attention-grabbing headline with a power word
- Start with a hook that presents a surprising statistic or counterintuitive insight
- Use the AIDA framework (Attention, Interest, Desire, Action)
- Include 5-7 subheadings (H2) optimized for SEO
- Add 3 actionable takeaways in a "Key Takeaways" box at the top
- End with a specific CTA
- Naturally incorporate these keywords: [KEYWORD 1], [KEYWORD 2], [KEYWORD 3]

Format the output in Markdown with proper heading hierarchy.
```

### Example Use:
- **Topic:** "AI tools for small business owners"
- **Audience:** Non-technical small business owners, age 30-55
- **Tone:** Conversational
- **Keywords:** "AI for small business," "AI productivity tools," "automate business tasks"

### Expected Result:
A publish-ready blog post with SEO-optimized headings, natural keyword integration, engaging intro, and clear structure that would typically take 3-4 hours to write manually.

## Prompt #11: The Code Review Partner

### Prompt:
```
Review the following code as a senior engineer conducting a thorough code review. Be constructive but honest.

```[LANGUAGE]
[PASTE YOUR CODE]
```

Review criteria (rate each 1-10):

1. **Correctness** — Does it do what it's supposed to?
2. **Readability** — Can another developer understand this in 60 seconds?
3. **Performance** — Any obvious bottlenecks or O(n²) traps?
4. **Security** — Input validation, injection risks, auth issues?
5. **Error Handling** — Edge cases, graceful failures?
6. **DRY/SOLID** — Repeated logic, single responsibility violations?
7. **Testing** — Is this testable? Suggest key test cases.

For each issue found:
- 🔴 Critical (must fix)
- 🟡 Improvement (should fix)
- 🟢 Nitpick (nice to have)

Provide:
- The specific line/section
- What's wrong
- How to fix it (with code)
- Why it matters

End with an overall rating and the single most impactful improvement.
```

### Example Use:
Paste a 100-line Python function that handles user authentication.

### Expected Result:
A structured code review with prioritized issues, specific fixes, and educational explanations — like having a senior engineer pair-program with you on demand.

# 📋 APPENDIX

## How to Get Even Better Results

### 1. Chain Your Prompts
Don't ask for everything at once. Use these prompts as starting points, then follow up:
- "Make the tone more casual"
- "Expand on point #3"
- "Give me 5 more options like option B"
- "Now adapt this for LinkedIn instead of Twitter"

### 2. Provide Context
The more context you give, the better the output:
- ❌ "Write a blog post about AI"
- ✅ "Write a blog post about AI productivity tools for non-technical small business owners who are skeptical about AI but curious. Tone: friendly expert. Length: 1,500 words."

### 3. Use Role Prompting
Starting with "You are a [EXPERT ROLE]" consistently improves output quality. Every prompt in this pack uses this technique.

### 4. Iterate, Don't Regenerate
If the output is 70% right, give specific feedback on the 30% that's wrong rather than starting over:
- "Great structure, but make the examples more specific to SaaS"
- "Love points 1-3, but point 4 is too generic. Replace with something more actionable"

### 5. Save Your Best Outputs as Templates
When you get a response that's perfect, save it. Next time, paste it as an example:
- "Write something in this style: [PASTE EXAMPLE]"
